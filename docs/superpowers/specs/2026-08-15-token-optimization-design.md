# Token 消耗优化设计

## 背景

项目的主要 token 成本来自 Agent 上下文中的规则文本和显式 live eval，而不是 Node.js 安装器或六个适配器。当前相同语义分散在 `SKILL.md` frontmatter、Skill 正文、全局策略和 Codex 默认提示中；代码写入任务会自动加载这些内容。`npm run eval -- --agent <id>` 还会默认启动 20 次独立模型会话。

不同 Agent 使用不同 tokenizer，无法用一个精确 token 数作为跨平台契约。本设计使用 UTF-8 字节、Unicode 字符和模型调用次数作为稳定指标，并以真实 smoke 验证行为没有失真。

## 目标

- 保留项目唯一职责：自动生成规范、简洁、清晰且耐维护的代码注释。
- 保留自动触发、默认简体中文、用户指定语言优先、三种注释模式和两阶段完整 diff 审查。
- 将仓库可控的运行时提示负担至少降低 33%。
- 将日常 live eval 从 20 次模型调用降到 8 次，完整 20 案例仍可显式运行。
- 通过确定性预算测试阻止提示文本再次无约束增长。

## 非目标

- 不压缩不会进入模型上下文的安装器、适配器或事务代码。
- 不删除行为案例、grader 分支或正式 Agent 适配器。
- 不批量合并多个 live eval 案例，避免案例互相污染和扩大单次失败范围。
- 不引入特定模型的 tokenizer 依赖，也不宣称字符数等于账单 token。
- 不改变安装、卸载、诊断或发布格式。

## 当前基线

### 运行时提示

| 内容 | UTF-8 字节 | 字符 | 加载时机 |
| --- | ---: | ---: | --- |
| frontmatter description | 752 | 282 | Skill 发现上下文 |
| Skill 正文 | 6,696 | 2,646 | Skill 触发后 |
| 全局策略模板 | 1,465 | 589 | Agent 常驻规则 |
| Codex default prompt | 447 | 435 | Codex Skill 调用入口 |
| 合计 | 9,360 | - | 仓库可控提示负担 |

渲染后的单 Agent 常驻策略为 665 至 715 个字符。代码写入任务加载 Skill 后，仓库可控上下文约为 3,925 至 3,975 个字符。

### Live eval

- 默认 20 个案例，每个案例启动一个独立 Agent 会话。
- 20 个原始案例提示合计 7,988 字节。
- 每个案例重复约 831 个字符的输出协议，20 次直接提示合计约 23,006 个字符。
- 18 个正例还会加载 Skill；所有案例都会加载对应 Agent 的全局策略。
- 六个 Agent 全量运行等于 120 次模型会话。
- `npm test`、`npm run validate` 和 `npm run check` 均为确定性命令，不调用模型。

## 运行时提示分层

### 全局策略

全局策略只负责让代码写入任务自动加载 Skill，并强制执行两个阶段：实现时记录关键意图，结束前审查完整 diff 和未跟踪交付文件。Skill 在编辑前加载一次，同一规则贯穿两个阶段；不得用“结束前再次使用”暗示重复读取完整 Skill。

全局策略保留纯只读例外和最终审查报告要求，模式、语言和注释质量细节交给 Skill 正文，不再重复展开。

### Frontmatter

`description` 只回答何时触发：创建、修改、重构或修复代码，以及用户明确要求生成、更新或审核代码注释时使用。普通只读解释和代码审查不隐式触发；明确审核注释仍可触发。

模式算法、语言优先级和完整 diff 流程不再复制到 description。

### Skill 正文

`SKILL.md` 是行为规则的唯一权威来源，合并为四部分：

1. 判断写入或只读任务，锁定 `SCOPED`、`GROUPED` 或 `STRICT`，确定语言、粒度和关注点。
2. 对代码写入执行实现阶段和完整改动审查阶段；只读任务按例外处理。
3. 执行高价值注释、现有注释、跨调用契约、格式和文件边界规则。
4. 只复用已经正常触发的辅助 Skill 结论，不主动扩大职责或重复分析。

以下语义不得压缩掉：

- `STRICT` 仅由正向、显式全称逐行约束触发。
- `GROUPED` 仅由正向逐行等价请求触发，且请求没有全称约束。
- 否定式逐行或全称提及保持 `SCOPED`；缺少全称约束本身不能触发 `GROUPED`。
- `line-by-line`、`一行ずつ` 等跨语言表达使用相同模式算法。
- 注释语言优先级为用户明确指定、项目就近规范、简体中文。
- 保留准确的现有注释及其语言，只更新失真、错误或冲突的注释。
- 终止符容量、失败路径资源释放和所有权转移等跨调用契约必须贴近相关分支或转移点记录。
- `GROUPED` 按语义块注释；`STRICT` 覆盖每条可执行语句但不单独注释结构行。
- 标准 JSON、锁文件、生成代码、第三方依赖及不支持注释的格式不得写入非法注释。
- 没有维护上下文时允许不新增注释，但代码写入任务的最终回复必须报告审查结果。

### Codex 元数据

`agents/openai.yaml` 只保留显示信息、简短的 Skill 调用提示和 `allow_implicit_invocation: true`。模式算法和两阶段流程由 Skill 正文负责。

## Live Eval 分层

### 默认核心集

`npm run eval -- --agent <id>` 默认运行以下 8 个正交案例：

1. `java-high-value-write`
2. `c-buffer-fix`
3. `english-grouped-line-comments`
4. `strict-english-per-line`
5. `self-explanatory-write`
6. `preserve-existing-english`
7. `json-no-comments`
8. `read-only-explanation`

该集合覆盖高价值业务与并发意图、资源和容量边界、跨语言 `GROUPED`、`STRICT`、无需强加注释、现有注释保留、不支持注释的格式和只读豁免。

### 完整集与定点运行

- `npm run eval:full -- --agent <id>` 运行全部 20 个案例。
- `npm run eval -- --agent <id> --case <ids>` 继续支持定点运行。
- `--full` 与 `--case` 互斥，冲突时在启动 Agent 前失败。
- 未知案例仍在启动 Agent 前失败并给出明确错误。
- 全部 20 个确定性 grader 案例继续由 `npm test` 覆盖。

完整 live eval 用于发布前、Skill 规则变化或显式全面回归，不进入默认 CI。

### 输出协议

保留现有 JSON schema 和 grader 字段，避免改变评测语义。合并重复说明并依赖字段名称表达显然含义，将每次重复协议控制在 500 个字符以内。协议仍必须明确：唯一 JSON 对象、正确 `case_id`、模式值、无 Markdown 围栏、源码注释清单与覆盖数量、JSON 禁止注释以及简短审查说明。

## 预算与防回涨

新增确定性提示预算测试，至少约束：

| 指标 | 当前值 | 上限 |
| --- | ---: | ---: |
| 四层运行时提示合计 | 9,360 字节 | 6,200 字节 |
| frontmatter description | 282 字符 | 170 字符 |
| 完整 `SKILL.md` | 2,978 字符 | 2,100 字符 |
| 全局策略模板 | 589 字符 | 360 字符 |
| 渲染后任一 Agent 常驻策略 | 715 字符以内 | 450 字符 |
| `agents/openai.yaml` | 603 字符 | 300 字符 |
| eval 重复输出协议 | 831 字符 | 500 字符 |

预算按 UTF-8 字节和 Unicode 字符计算，不引入运行时依赖。预算失败必须报告具体文件和实际值，便于判断新增文本是否值得永久承担。

## 测试策略

- 先新增失败测试，固定提示预算、8 个默认案例、20 个完整案例、`--full` 与 `--case` 互斥规则。
- 调整 Skill 契约测试，使每层只验证自己的职责；不再要求同一模式算法同时出现在 frontmatter、全局策略和 Codex 默认提示中。
- Skill 正文测试继续覆盖全部不可退化语义。
- 行为案例、grader、语法验证和六个 Runner 契约全部保留。
- 运行 `npm run check` 和 `npm pack --dry-run`。
- 将候选版本安装到当前用户环境后，运行一次 Codex smoke，验证隐式触发、Skill 读取先于编辑、完整 diff 审查、克制的中文注释和最终审查报告。
- 不自动运行完整 20 案例 live eval；维护者可通过 `eval:full` 显式执行。

## 文档与兼容性

README 更新运行时提示分层、核心与完整评测命令、模型费用说明和实际 20 案例数量。现有 `eval --case` 调用保持兼容；不带 `--case` 的默认范围从完整集变为核心集，属于有意的维护命令成本优化，不影响安装后的注释行为。

Release 包仍包含同一套 Skill、策略和 Node.js CLI，不增加依赖或平台专用资产。

## 验收标准

- 四层运行时提示合计不超过 6,200 UTF-8 字节，相比基线至少减少 33%。
- 默认 live eval 恰好启动 8 次模型会话，相比原 20 次减少 60%。
- `eval:full` 仍能选择全部 20 个案例，`--case` 可定点选择。
- 全部确定性测试、校验和打包检查通过。
- Codex smoke 通过，自动触发、两阶段流程和注释质量未失真。
- 安装、卸载、doctor、六个适配器和发布流程保持兼容。
