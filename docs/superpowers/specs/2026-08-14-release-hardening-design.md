# 发布加固设计

## 目标

在不扩展项目职责的前提下，修复安装器的数据安全问题，提高代码注释行为评测的可信度，并收紧发布产物。项目仍只负责让受支持的 Agent 自动生成规范、简洁、清晰且可维护的代码注释。

## 所有权与状态

- 状态升级为 schema v2，记录每个存储组的成员、实际根目录、受管文件路径、内容摘要和所有权。
- 安装前已存在且内容相同的 Skill 视为外部引用，不被完整安装器接管；已有有效安装状态或旧版受管规则能够证明来源时才迁移为本项目所有。
- 卸载只删除状态明确拥有、路径与安装时一致且内容未漂移的文件。外部引用、失效状态、改根后的同名文件和用户修改过的 Skill 均保留并产生明确 warning。
- schema v1 在下一次安装时迁移到 v2；无法安全证明所有权时采用保留策略。

## 并发

- 所有会读取或修改安装状态的命令使用 `~/.chinese-code-comments/installer.lock` 用户级互斥锁。
- 锁通过 Node.js 排他创建实现，持有者在 `finally` 中释放；超时后仅回收能够证明进程已结束的陈旧锁。
- 锁覆盖读取状态、构造事务和提交的完整区间，避免两个成功命令互相覆盖状态。

## 安装入口与验证

- README 中完整安装器统一使用 HTTPS Git spec，不要求 GitHub SSH 或 22 端口。
- live eval 分开报告直接 Skill 轨迹、行为结果和无法确认，不允许最终自述单独证明 Skill 已被读取。
- 评测对 Python、Java、C 和 C++ 使用真实语法检查；缺少工具链时明确报告基础设施错误，而不是降级为通过。
- Java smoke 保留方法签名，编译返回源码并执行并发重复回调测试；不得使用 JavaScript 集合模拟 Java 行为。
- C 缓冲区案例关联分配容量、接收上限和终止符写入，拒绝容量不匹配的实现。

## 文件与发布兼容

- 事务替换现有文件时保留 POSIX mode。
- 允许配置目录经过符号链接或 Windows junction；目标文件自身是链接时继续拒绝，避免替换链接指向关系。
- `package.json` 增加发布白名单、仓库、主页、问题地址和关键词。
- eval 定义使用显式 `case_id` 关联，不再依赖数组顺序；所有行为案例必须进入 grader 或被明确删除。

## 验收

- 新增测试必须先在旧实现上失败，再由最小实现修复。
- Windows、macOS、Linux 的确定性 CI 通过。
- `npm run check`、`npm pack --dry-run` 和 `git diff --check` 通过。
- 完整 diff 通过 `chinese-code-comments` 注释审查，无重复、失真或解释显而易见代码的注释。
