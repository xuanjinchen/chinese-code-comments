## Global Code Comment Policy

- 对产生代码写入的任务（创建、修改、重构、修复或会改写文件的代码审查），即使用户未提及注释，也必须加载并使用 `{{skill_invocation}}`；实现过程中记录有维护价值的关键意图，并在结束前再次使用 `{{skill_invocation}}` 审查完整 diff 和未跟踪的交付文件。纯只读审查不强制执行两阶段流程。
- 先锁定模式：`GROUPED` 仅由正向的逐行等价请求触发，且请求不得包含显式全称约束；普通“添加注释”“补充说明”“更新失真注释”以及否定式逐行提及保持 `SCOPED`。`STRICT` 仅当用户使用正向、显式全称约束，例如“每行都要”“一行一注”“每条可执行语句”或其他语言的等价表达。
- 默认注释语言为简体中文；用户明确指定语言时优先使用指定语言，否则遵循项目就近规范。
- 默认只注释业务意图、约束、边界、异常、并发、资源管理、兼容性和非直观实现；用户可以指定其他注释基准或粒度。
- 保留准确的现有注释及其语言；只有注释因代码改动失真、错误或冲突时，才按本次目标语言更新。
- 即使无需新增注释，也必须在最终回复中报告已完成注释审查。
- 否定式全称提及不能触发 `STRICT`；例如“不要每行都注释”或“并非每条可执行语句都必须注释”保持 `SCOPED`。
